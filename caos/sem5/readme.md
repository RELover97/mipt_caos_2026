# Стек и вызов функций

Соглашение о вызовах в Linux x86 (**calling convention**) - **System V AMD64 ABI**:

- первые 6 аргументов функции передаются через регистры `rdi`, `rsi`, `rdx`, `rcx`, `r8`, `r9`

- прочие аргументы передаются в стеке, причём лежат в памяти "по порядку" (адрес возрастает вместе с ростом порядкового номера аргумента)

- параметры удаляет из стека тот, кто их туда положил, то есть вызывающая функция

- возвращаемое значение кладётся в регистр `rax` (для 128-битного значени - в пару `rdx:rax`)

- регистры, которые должна сохранять вызываемая функция (**callee-saved registers**): `rbx`, `rsp`, `rbp`, `r12`, `r13`, `r14`, `r15`

- регистры, которые должна сохранять вызывающая функция (**caller-saved registers**): все остальные, то есть `rax`, `rcx`, `rdx`, `rsi`, `rdi`, `r8`, `r9`, `r10`, `r11`

- перед выполнением инструкции `call` `rsp` должен быть выровнен по 16 байт


Инструкция **call**:

- кладёт на стек адрес возврата (адрес следующей инструкции)
- делает безусловный переход на заданную метку (`jmp`)
```
call label
```
```
lea rax, [rip + 4]
push rax
jmp label
```

Инструкция **ret**:

- достаём со стека адрес возврата из функции
- переходим по этому адресу
```
ret
```
```
pop rdx
jmp rdx
```

Пролог и эпилог функции необязательны по соглашению, но могут быть нам удобны для отладки и работы с локальными переменными на фрейме функции. 

Типичный **пролог** функции:
```
push rbp
mov rbp, rsp
```

- кладём адрес предыдущего фрейма на стек
- сохраняем в `rbp` адрес начала фрейма текущей функции

Типичный **эпилог** функции:
```
mov rsp, rbp
pop rbp
ret
```
```
leave
ret
```

- устанавливаем `rsp` на начало кадра текущей функции
- кладём в `rbp` адрес начала предыдуего кадра
- извлекаем со стека адрес возврата из функции (который положила на стек `call`) и переходим по нему
